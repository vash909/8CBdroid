# Desktop payload and hash fixtures (R03b)

`packing.json` is generated by compiling the real `pack77`, `pack77var`,
`unpack77var`, `ihashcall`, hash lookup/learning and `fillhashvar` routines from
WSJT-CB `94f776d54946fe43db5e0bb9c966b1595c7b7d97`. The nine unmodified source
files, including the existing CB predicates and the legacy `packjt` include,
are pinned in `packing-sources.json`. Preserve their original bytes, whitespace
and line endings; `.gitattributes` disables Git text conversion for these files.
They remain under the upstream GPLv3 terms; see [notices](../../THIRD_PARTY_NOTICES.md).

The input-only `packing-cases.json` contains 67 messages, 15 calls for hash
vectors and 79 scenarios. It covers short/long, numeric and slash CB calls,
leading zeros, both type 4 hash orientations, finals, destination-only signed
reports, standard-call controls, normalization, free-text fallbacks and malformed
calls. Every packed message has a separate cold RX scenario. Additional scenarios
exercise pending versus committed learning, CQ and directed-message learning,
local station identity, an unrelated learned call, real hash collisions, invalid
payload characters and reserved message types.

## Run and review

Use Linux with Python 3 and GNU Fortran (`gfortran`, or `FC` and optional
`FFLAGS`). No network, Qt, FFTW, NDK or radio is needed:

```bash
python3 scripts/wsjtcb_packing.py --check
python3 scripts/wsjtcb_packing.py --check --optimization O2
python3 -m unittest discover -s scripts/tests -p 'test_wsjtcb_*.py'
```

Run without `--check` to intentionally regenerate `packing.json`, then review
the payloads, decoded text, success flags and hash-state transitions. A changed
source byte or mismatched reference revision fails before compilation. CI checks
the committed fixture at both `-O0` and `-O2`, with bounds/runtime checks enabled.
`-fwrapv` preserves the hash's intended signed 64-bit wraparound. The Linux linker
discards unused legacy routines with function/data sections and `--gc-sections`;
no reference algorithm or unresolved dependency is replaced with a stub.

Each packer invocation and each RX scenario runs in a fresh process. Packing
therefore cannot warm the receiver's tables, and scenarios cannot leak identities
to each other. Module state persists only across steps within one scenario.
The harness uses one decoder worker (`nthr=1`) and received-message unpacking
(`nrx=1`). It is not a decoder concurrency or TX-preview test.

## Fixture format

The JSON header records schema version 1, repository/revision and SHA-256 values
for the source manifest, inputs and harness. It has no timestamps or host paths.

| Field | Meaning |
| --- | --- |
| `packing` | Input and both production packers' `i3`, `n3` and exactly 77 payload bits. |
| `hashes` | Upstream 10-, 12- and 22-bit hash integers for each complete call. |
| `scenarios` | Ordered input operations with actual unpack success/text or resolved hash results. |

The packers receive `i3=n3=-1` before each call. These output integers are the
routine results: `n3` can remain `-1` when `i3=4`; it is a subtype only where the
message format defines one. Do not interpret the final six bits of every message
as two independent type fields. The 77 bits are authoritative.

Scenario operations are `decode` (a packed case ID), `raw` (explicit 77-character
input), `learn` (enqueue a full call through `save_hash_callvar`), `commit` (merge
pending calls through `fillhashvar`, then start a new pending batch), `station`
(set local identity through `fillhashvar`) and `lookup` (width plus call whose hash
is queried). `decode` uses the `pack77` payload; both packers produce identical
results for this corpus, which the native integration tests also verify.

## Results that constrain the Android implementation

- A cold `<1AT106> 26AT101` unpacks successfully as `<...> 26AT101`. Enqueuing
  `1AT106` does not immediately resolve it; committing the pending table does.
  Receiving `CQ 1AT106` teaches the same identity after that merge.
- Local station identity resolves the leading type 4 hash on RX, while the
  trailing type 4 hash can remain unresolved until the call is learned. These
  orientations need distinct tests.
- `1AT0002` and `1AT0050` share hash10 `482` and hash12 `1928`, but have different
  hash22 values. `5AT179` and `10AT107` share hash22 `2524178`. In the tested RX
  tables, the last learned call replaces the previous identity. An Android hash
  cache must treat a resolved hash as evidence with collision limits; the desktop
  text alone does not prove a unique peer or authorize AutoSeq.
- `1AT106 26AT101 -10` falls back to free text and unpacks as `1AT106 26AT10`.
  `<1AT106> 26AT101 -10` packs as type 4 without the report. `CQ 1AT106 JN45`
  loses the locator. A successful unpack is not proof that the original text
  survived; compare the actual result before allowing a future transmission.
- Destination-only `26AT101 R-10` and `26AT101 RR73` survive their free-text
  encodings. R03c's [QSO traces](QSO.md) verify the messages the desktop generates.
- The packer can emit a payload whose type 4 unpack fails (for example
  `CQ 53HDFKJEASD`). Grammar, packing, unpacking and QSO admission are separate.

These are payload fixtures, not 174-bit LDPC codewords, CRC checks, tones or audio.
A binary payload with a flipped bit may still describe another valid message;
the reserved-type and non-binary-input checks do not establish corrupt-frame
rejection. No app encoder, decoder, hash cache, CAT/PTT or AutoSeq is added.

## Phone smoke test

Install the PR's `8CBdroid-debug` APK and open Station, LAN and Radio. Check that
saved settings restore, LAN listening/decodes still work with WSJT-CB, and USB
discovery opens. There are no new screens. These checks cover app regressions;
the host reference job validates R03b. OTG hardware is not required for this PR.
